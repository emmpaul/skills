# Design

## Context

Each `ep-*` skill is a self-contained folder containing `SKILL.md`, a synced `scripts/context.sh`, and optionally `references/` (`ep-review` has `references/dimensions.md`). `scripts/sync-shared.sh` and `scripts/check-shared.sh` loop over every `skills/*/` folder that has a `SKILL.md`, so a new skill must ship the probe copy or `check-shared.sh` fails. The maintainer scripts in this repo use bash, and the runtime probe avoids `jq`.

W3C publishes a machine-readable WCAG 2.2 source at `https://www.w3.org/WAI/WCAG22/wcag.json`, built from the `w3c/wcag` repository. Fetching it on 2026-11-06 gave this structure: `principles[] → guidelines[] → successcriteria[]`. Each criterion has `id`, `num`, `handle`, `title`, `level`, `versions`, `content` (HTML), `details`, and `techniques` (`sufficient`, `advisory`, and `failure`, each with technique `id` and `title`). There is also a top-level `terms[]`. The file holds 87 criteria: 31 A, 24 AA, 31 AAA, and 4.1.1 Parsing with an empty level and `versions` of `["2.0","2.1"]`, which is how 2.2 marks it obsolete.

See proposal.md for why, and specs/ep-a11y/spec.md for the required behavior.

## Goals / Non-Goals

**Goals:**
- Updating WCAG takes one command plus a review of the diff. A version bump changes one setting.
- Generated output is deterministic, so a regeneration diff shows only real WCAG changes.
- The skill reads a small index and only the criterion files it needs.

**Non-Goals:**
- Rendering pages or computing contrast from a running app. The audit reads code, and rendered checks go on the manual-check list.
- Installing axe, pa11y, Playwright, or any other tool in the target project.
- WCAG 3.0. Its structure is different, so it would need a separate generator.
- Changing `ep-review` or making it call `ep-a11y`. That can be a later change.
- Section 508, EN 301 549, or other legal mappings.

## Decisions

### D1. Layout

```
scripts/wcag.py                      maintainer tool (update | update --dry-run | check)
skills/ep-a11y/
  SKILL.md
  scripts/context.sh                 synced copy of shared/context.sh
  references/
    checks.md                        hand-written: detect + fix guidance per criterion
    audit.md                         hand-written: finding shape, severity, verification, manual checks
    wcag/                            generated: never edit by hand
      index.md                       table of all criteria + W3C attribution
      manifest.json                  source url, version, fetched_at, source_sha256, files{path: sha256}
      sc/<num>-<id>.md               e.g. sc/1.1.1-non-text-content.md
```

The generator lives at the repo root, not in the skill. The installed skill never regenerates anything, so it does not need to ship the tool. This keeps the skill self-contained without putting anything in `shared/`, because no file is copied across skill folders.

### D2. Source: W3C `wcag.json`

`wcag.py` reads `https://www.w3.org/WAI/WCAG{VER}/wcag.json`, where `VER = "22"` is the single version setting at the top of the script. It can be overridden with `--version` or `--source <file-or-url>`, which allows offline regeneration and test fixtures.
- Alternative: scrape the TR HTML. Rejected because it breaks on markup changes, and W3C publishes JSON for exactly this purpose.
- Alternative: write the files by hand and keep an update checklist. Rejected because 87 files drift silently, and an agent editing them reintroduces the very errors this change exists to remove.
- Alternative: a git submodule of `w3c/wcag`. Rejected because `npx skills add` copies the skill folder only, and the raw repo would need a build step.

### D3. Generated file format

Each `sc/<num>-<id>.md` file contains:
- A first line `<!-- GENERATED by scripts/wcag.py from <source url>. Do not edit; run scripts/wcag.py update. -->`.
- A heading `# <num> <handle> (Level <level>)`.
- Versions, and an `Obsolete` marker when the level is empty.
- The normative text: `title`, then `content` and `details` converted from HTML to Markdown with the standard library's `html.parser`. Paragraphs, lists, notes, and definition links are kept; definition links become absolute links to TR.
- Links to the Understanding document and the TR anchor.
- Sufficient techniques and failures as lists of `ID: title`. Advisory techniques are dropped to keep the files small.

`index.md` has one row per criterion: num, handle, level, versions, obsolete, file. It is grouped by principle and guideline and ends with the W3C copyright and Document License notice that the license requires when copying text.

Determinism: the generator walks in source order, writes LF line endings, and puts no timestamps in the `.md` files. `fetched_at` exists only in `manifest.json`, so regeneration from an unchanged source changes only that field.

Atomic write: the generator builds into a temporary directory, validates the result (at least one principle, and every criterion has `num`, `handle`, and `level` present, even if empty), then replaces `references/wcag/`. A failure at any step leaves the old tree in place.

### D4. Hand-written guidance keyed by criterion

`checks.md` has one `## <num> <handle>` section per criterion where code-level detection is possible. Each section covers what to look for in markup, components, and CSS, the common false positives to rule out during verification, and the preferred fix. Criteria without a section are still auditable from their generated file. `wcag.py check` parses `^## (\d+\.\d+\.\d+)` headings and inline `SC <num>` references, and compares them against the index.
- Alternative: inline the guidance in the generated files between preserved markers. Rejected because merging generated and hand-written content is the main source of maintenance pain, and keeping them in separate files makes the boundary obvious.

`audit.md` holds the finding shape, the severity scale, the verification checklist, and the default manual-check list. This mirrors `ep-review/references/dimensions.md`, so that `SKILL.md` stays short.

### D5. `wcag.py` modes

- `update`: fetch, validate, generate into a temp dir, swap it in, and write the manifest. Print counts of added, removed, and changed criteria.
- `update --dry-run`: fetch and generate into a temp dir, diff it against the current tree by criterion, print the result, and write nothing. Exit 0 either way, and print `up to date` when the source hash matches the manifest.
- `check` (offline): recompute each generated file's sha256 against the manifest; confirm the index rows and the `sc/` files match one to one; confirm every criterion cited in `checks.md` and `audit.md` exists and is not obsolete. Exit 1 with a list of problems.

CI runs `python3 scripts/wcag.py check` and `python3 -m unittest scripts/test_wcag.py`. The unit tests generate from a small fixture (`scripts/fixtures/wcag-mini.json`, with one normal criterion, one obsolete criterion, and a malformed variant), so they need no network.

Python 3 with only the standard library (`urllib`, `json`, `hashlib`, `html.parser`) was chosen over bash and `jq`. Converting HTML to Markdown and walking nested JSON in bash would be fragile. This is maintainer-only tooling, so the runtime skill stays free of a Python dependency.

### D6. Audit flow (SKILL.md)

1. Run `scripts/context.sh` (or the inline fallback) to get the git and PR state and the default branch.
2. Resolve the target and get the diff, using the same table as `ep-review`. For a path target, use the whole file content.
3. Filter to UI files by extension (`html`, `htm`, `jsx`, `tsx`, `vue`, `svelte`, `astro`, `css`, `scss`, `less`, and templates such as `erb`, `hbs`, `njk`, `jinja`, `twig`, `liquid`, `cshtml`, `razor`), plus `.js` and `.ts` files that render markup. If none remain, report `nothing to audit`.
4. Read `references/wcag/index.md` and filter it to the in-scope levels, excluding obsolete criteria. Read `references/checks.md`.
5. Audit by principle (P, O, U, R). For each candidate, open its `sc/` file to confirm the criterion text before citing it.
   - **Subagent path:** four parallel subagents, one per principle. Each gets the diff, the in-scope index rows for its principle, `checks.md`, and `audit.md`, and returns candidates in the finding shape.
   - **Sequential fallback:** the same four passes run one after another in the main context. The output shape is identical.
6. If the project's package scripts or Makefile already define an a11y test (a script name containing `a11y`, `axe`, or `pa11y`), ask the user before running it, and never run one that the target's diff defines or changes, since that would run code from the change under audit. Add its failures as candidates.
7. Verify each candidate against the `audit.md` checklist: a name supplied elsewhere, `aria-hidden` or `inert`, a wrapper or design-system component, or decorative use. Drop anything that does not survive, and correct or drop any citation the index lacks.
8. Assign severity by impact (D7), rank the findings, and add the manual-check list.
9. Optionally `--fix` (D8), then print the report, optionally `--comment` (D8), and end with the summary block.

### D7. Severity by impact, not level

- **critical:** some users cannot complete the task. Examples: a keyboard trap, an unreachable or unoperable control, a form field with no accessible name, a focus order that loses focus.
- **major:** the task is possible but significantly harder or wrong for assistive-technology users. Examples: a wrong role or state, missing error identification, focus hidden behind a sticky header (2.4.11).
- **minor:** low-impact or partial. Examples: a redundant or verbose alt text, a missing `autocomplete` token on a rarely used field.

### D8. Gates

| Action | Gate |
|---|---|
| Edit working-tree files | `--fix` only. For PR targets, also requires the current branch to equal the PR's `headRefName`, and for branch targets the current branch to be that branch; otherwise the skill reports only. Never touches files outside the audited set. |
| Run a project a11y test command | Only after the user confirms the exact command, and never when the target's diff defines or changes it. |
| Commit or push | Never. The user commits, for example with `ep-commit`. |
| Post to GitHub | `--comment` with a PR target only, using one `gh pr comment <n> --body-file`. No attribution. |
| Install tools | Never. |
| Overwrite `references/wcag/` | Maintainer runs `wcag.py update` explicitly. It writes atomically and aborts on a bad source. `--dry-run` writes nothing. |

### D9. Summary block

```ep-a11y-summary
target: <diff|branch:<name>|pr:<n>|paths>
wcag: 2.2
level: AA
references: <manifest version> sha256:<first 12 of source_sha256>
findings: {critical: n, major: n, minor: n}
manual_checks: n
fixed: true|false
commented: true|false
```

## Risks / Trade-offs

- [W3C moves or renames `wcag.json`] → The URL is one setting and `--source` takes a file. `update` fails loudly and keeps the old files.
- [W3C changes the JSON shape] → `update` validates the structure before writing and aborts with the missing key. The existing references stay usable.
- [HTML-to-Markdown conversion loses nuance (tables, nested notes)] → Every file links to TR and the Understanding document. The converter falls back to plain text for unknown tags rather than dropping them.
- [`checks.md` falls behind when a criterion changes meaning] → `check` catches removed or obsolete criteria, but not changed meaning. The `update` output lists changed criteria so the maintainer can review their `checks.md` sections, and the README procedure says to do so.
- [A static audit misses runtime issues (computed contrast, dynamic focus)] → These go on the manual-check list, the report never claims conformance, and existing a11y test commands are used when present.
- [False positives from component abstractions] → The verification step requires checking wrapper and design-system components before reporting.
- [Context size] → The index has about 87 rows, and criterion files are opened on demand.
- [License] → The W3C Document License allows copying with the notice; `index.md` and `manifest.json` carry it.

## Migration Plan

This change is additive. To roll back, delete `skills/ep-a11y/` and `scripts/wcag.py` and revert the README rows. No existing skill changes.
